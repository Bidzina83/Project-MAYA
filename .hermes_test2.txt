Suggested replacements (pattern -> replacement template)
1) Curl calls that create PRs using a token
- Pattern (examples found in sessions):
  curl -s -X POST -H "Authorization: token $TOKEN" -H "Accept: application/vnd.github+json" https://api.github.com/repos/$OWNER/$REPO/pulls -d @/tmp/pr_payload.json
- Replacement: call the GitHub App helper to create a PR (preferred, non-secret):
  /opt/hermes/.venv/bin/python3 /opt/data/scripts/github_app_pr.py --app-id <APP_ID> --pem /opt/data/.secrets/github-app/app.pem --owner $OWNER --repo $REPO --head <branch> --base <base> --file-path <file> --file-content @/tmp/file --pr-title "<title>" --pr-body @/tmp/pr_body.txt
  (If the original flow used an existing branch and payload, adapt flags accordingly.)

2) Git clone/push using embedded token in URL
- Pattern:
  git clone https://<TOKEN>@github.com/owner/repo.git
- Replacement:
  Use a clean remote URL and push via a repo with proper auth (App flow does not require embedding token in URL). Example remediation command:
  git clone https://github.com/owner/repo.git
  git remote set-url origin https://github.com/owner/repo.git
  # if pushing programmatically, use the App helper to create/modify files and open PRs instead of pushing directly

3) Script-side Python urllib / requests with header 'Authorization': 'token <PAT>'
- Pattern:
  req = urllib.request.Request(url, headers={'Authorization': 'token ghp_xxx', ...})
- Replacement options:
  - If code runs on-host and has access to the PEM & app id, convert to the App JWT flow: generate JWT, exchange for installation token, and use that token in headers. You can call a small helper (wrap existing code around a function get_installation_token(app_id, pem_path, owner)) and reuse installation token for API calls.
  - Alternatively, replace with a call to github_app_pr.py for PRs or use 'gh api' with GH config set to the App token.
