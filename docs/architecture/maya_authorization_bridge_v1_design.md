## Handles And Lifecycle

The restricted child still inherits exactly stdin-read/stdout-write/stderr-write,
and no file, token, gateway-worker process, job or policy/audit handle. Retain the
parent stdin-write end, currently closed during startup. Stdout becomes a framed
protocol exclusively; stderr is bounded private diagnostics, never public output.
The coordinator does not authenticate via a PID supplied in a message. It binds
the actual process handle, start identity, checked token and channel endpoints
when creating the child. No named pipe, reconnect, shared bearer file or network
listener exists. All unnecessary pipe ends are non-inheritable/closed promptly.

Worker launch inherits only its own three pipe ends through an explicit handle
list; never the restricted child's endpoints or coordinator handles. The worker
has a separate one-process kill-on-close job. The existing restricted job retains
its one-process limit; no exception permits Hermes to spawn the worker. Coordinator
crash closes both jobs. Native verification of this new lifecycle is mandatory;
job flags alone are not cleanup proof.

Startup: verify payload and consent -> create protected host files -> launch and
verify worker token/job/ready identity -> prepare checked restricted child -> start
bounded channels -> resume child -> real Hermes registration/construction -> tests.
Any missing identity, worker readiness, audit or protection blocks child resume.
No product activation or unrestricted fallback. Shutdown revokes admissions first,
closes request input, stops/confirms both jobs, then removes child security resources.
Retain protected synthetic data/audit and bounded reports. New missing-journal or
worker-cleanup uncertainty reports cleanup_pending; never overwrite it with success.

## Wire Contract

Both channels use the same strict codec: four-byte unsigned little-endian length
followed by exactly that many UTF-8 bytes containing one JSON object. Length must
be 1..8192, no BOM, duplicate keys, NaN/Infinity, trailing material, invalid UTF-8,
unknown fields or recursive depth over 8. Validate declared length before allocation.
Read loops handle partial reads; EOF mid-header/body is terminal. No compression,
pickle, eval, code loading, serialized exceptions or arbitrary nested payloads.

Restricted request, exact fields:

    {"v":1,"type":"request","attempt":"<32 lowercase hex>",
     "lease":"<host 32-byte random token as 64 lowercase hex>","seq":1,
     "operation":"document.read","resource":"maya.synthetic.document.v1"}

The token travels only inside private pipes and memory, never argv/environment,
policy, report, diagnostic log or on disk. It authorizes no identity of its own.
The host binds it to one checked child/channel, authenticated operator SID,
attempt, fixed target/classification, operation, expiry and single effect budget.
No child actor/classification/path/URL/approval/result fields exist. Unexpected
fields are denied, not silently ignored. Secrets and provider keys never enter it.

Host grant envelope provides v/type=grant/attempt/lease/ttl_ms and the one allowed
operation/resource. It cannot be a child-issued message. Restricted requests do
not contain a case ID used to switch authority. The host case schedule selects
each fresh test lease and policy/fault fixture before sending it.

Response, exact fields:

    {"v":1,"type":"response","attempt":"...","seq":1,"status":"ok",
     "code":"bridge.document_read","data":{"text":"<synthetic text>"}}

On denial/error, data is null and code is a fixed allowlisted public reason.
Never echo the supplied token/path, policy, exception, raw request or document
bytes in an error. Unknown operation/target, extra identity fields and bad lease
consume/revoke that lease. Well-framed semantic denials permit a new host-created
lease on the same bound channel for the fixed test schedule; they never renew the
old lease. Sequence numbers increase across the channel, not just within a lease,
and responses must match the one outstanding sequence. Stale responses cannot
be accepted for a later lease. Framing errors/overflow/duplicate keys abort the
whole channel/attempt.
No unsolicited data, streaming, multiplexing, requests in flight or reconnection.

Worker private request contains a coordinator-owned request ID and bound identity,
not a forwarded child identity. Worker dispatch is document.read only. Authenticate
worker channel by its private creation/ready binding; validate responses to the
one outstanding request ID. Coordinator never interprets a worker response as an
OS command or accepts worker-initiated operations. No generic effect callback API.

## Authority, Audit And Disclosure

Bind actor_id = windows:<actual operator SID>, request_id from host randomness,
classification = internal-synthetic, fixed target ID and operation read.
Call the existing gateway with capability file.read BEFORE opening/reading the
document. Only a literal ALLOW with no unhandled redactions/constraints proceeds.
DENY/DEFER/confirmation/approver/redact/constrain/unknown outcomes block here;
the bridge does not implement an approval workflow by treating them as ALLOW.

State machine per lease:
issued -> admitted -> policy_checked -> read_intent_durable -> read_bounded ->
release_intent_durable -> release_committed -> response_sent -> consumed.
Any pre-commit failure goes to revoked with zero document bytes on the child
channel. A denial never becomes an allow because cleanup later succeeds.

Reuse AuditRecord and the local audit format, but LocalJsonlAuditSink currently
does not explicitly flush/fsync before returning. Required-audit durability must
be added through a reviewed backward-compatible implementation/adapter, not
assumed from the existing API. Do not replace the gateway. Audit events bind
actor/request/attempt/target/action, decision, payload/response digests, sequence
and lifecycle outcome, not raw document text or admission tokens. Validate exact
audit schema and require write+flush+fsync completion before protected read and
before release. Bounded local audit failure prevents further effects/disclosure.
This is not power-loss durability or immutable-audit qualification.

Serialize cancellation and release commitment under host-owned state control.
Check cancellation/expiry before read and again immediately before commitment;
check worker reply identity/length/schema and allowed content before enqueue.
Once release is committed, cancellation cannot recall already released bytes.
Record committed/sent/uncertain accurately; do not claim every racing cancel
prevents an earlier committed release. Never automatically retransmit a partial
or uncertain response. Worker/coordinator channel loss revokes all unused leases.

Before commitment require a separate existing-gateway decision file.disclose,
fixed runtime recipient bound to this attempt, and required audit. It authorizes
only this synthetic content into restricted context, not a final operator answer.
The A3 policy lists these two exact allows for the actual bound actor; no wildcard
actors/resources/operations. Protected-file access itself still uses file.read.
Document disclosure denied after authorized read means open_count may be 1 but
document_bytes_released must be 0. Never claim zero reads for post-read failures.

No raw Hermes stdout is shown as a validated answer. Public report uses fixed
codes/counts/hashes and host-derived predicates. A3 has no customer answer; final
operator/model disclosure will need its own policy/validation path in A4/B.

## Bounds And Evidence

Separate bridge compile/profile/version/resources; never mutate prior artifacts.
Keep Python 3.13.14/Hermes pin, payload caps 8192/4 MiB, per-file 32 MiB/expanded
256 MiB unless dependency closure proves a review is needed. No silent expansion.
Keep child 22-second cooperative/30-second host deadline. Worker readiness has
5 seconds before child resume; worker processing is capped at 2 seconds per call,
never beyond child deadline. Each incomplete frame has a 1-second read deadline.
Limits are conservative proposals, not measured native compatibility claims.

Fresh lease TTL 2000 ms from host monotonic issue time, one read/release maximum,
one request per lease, seq exactly the next channel value 1..16; no retry.
At most 16 leases and 16 child requests, one in flight.
Per channel direction 128 KiB cumulative; 8192 maximum frame; document 1024;
stderr 4096; public report 65536; host audit 128 KiB; fixed exact case count.
Count headers and payload bytes. Overflow kills/revokes, never truncate into a
valid message. Child stdout is protocol under these NEW profile-only caps, not
legacy 4096-byte startup text; startup/ready beacons become versioned frames.
Retain legacy behavior unchanged. Collectors must not race protocol readers.

Trustworthy evidence is host/worker-owned: actual policy/audit event ordering,
document-open/read/release counters, channel request binding, sent-byte counts,
canary digest equality, lifecycle/job status. Child observations are supporting
untrusted evidence. Direct-read denial additionally needs actual child failure
and verified descriptors, not solely an AccessCheck prediction. No public canary
is preseeded in child reports/config. Retained host artifacts stay private.

## Test Contract And Stop Conditions

See maya_authorization_bridge_v1_tests.json for exact case IDs, evidence tier and
expected effects. Local tests first: deterministic fake clocks/faulting I/O plus
actual codec/gateway/audit code, no native security/Hermes launch. Native first
package: one protected child, one trusted worker, one fixed ordered schedule of
12 cases/leases, one permitted real document release, no automatic second run.
Cases with pre-read failure require zero open/read/release; post-read denial
allows the declared read but never release. Case isolation uses new leases,
not process/session restart or blanket error recovery.

Coordinator control frames are separate exact schemas: hello/ready, grant,
case_complete and shutdown. They cannot authorize or dispatch effects. A child
case_complete carries only its fixed expected case ordinal and bounded Boolean/
error-code observations; the host's private schedule/counters decide the result.
N02 has no document request, only direct-open observations followed by this
control frame. Requests consume channel sequence numbers; control frames do not.
Grant supplies next_seq; case_complete binds the active ordinal and last request
sequence. All frame/cumulative bounds apply. Unexpected control ordering is
terminal. Readiness is not a fabricated Python startup beacon.

All local cases must pass before package assembly. Native package requires
separate exact-artifact/impact approval and product consent. Local-only fault
tests remain explicitly NOT native qualification. An unexpected positive or
negative result stops the schedule, revokes and cleans up; no tuning/retry.

Pass requires exact frozen identity, actual real-agent/tool binding, all 12
native cases observed with no missing/inconclusive evidence, exact one allowed
release, zero denied releases, bounded natural child/worker exit and product
cleanup. Status: bridge_document_completed_pending_independent_cleanup. All
production/containment/independent-cleanup qualification flags remain False.
Timeout, missing audit, unexpected access, malformed response, unknown outcome
or cleanup uncertainty blocks. Do not turn an IPC success into Gate A acceptance.

Post-run independent checks cover both process identities/jobs where observable,
host/child ACLs, reparse points, child package-SID cleanup, restored state integrity,
six filters/sublayer and retained audit integrity. Profile deletion remains an
explicit gap until independently evidenced. Retained host ACLs are intentional,
not cleanup residue to remove automatically. No manual OS conditioning.
