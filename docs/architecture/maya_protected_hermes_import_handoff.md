# Maya Protected Hermes Import 1

## Scope And Approval

The user approved bounded import-package preparation, an import-only 8,192-file /
4-MiB inventory envelope, and acquisition of exact verified prebuilt wheels.
No native Hermes import or VM run is part of preparation. Obtain separate
artifact/run approval and fresh in-product consent for one RDP VM attempt.
Do not run this executable on the development workstation.

The component uses the existing consent/setup/restricted-launch/report/cleanup
implementation with the HERMES_IMPORT build profile. The default Screen 11
profile keeps its 2,000-file/1-MiB limits and synthetic probes. Frozen prior
packages and reports are not changed. This is not another supervisor or VM
test runner, and no VM/Docker dependency is added to the product.

## Exact Import Objective

Load the real run_agent module from Hermes commit
b13e2fd6948a59eeb59fe618914147d97a2ee90a, verify its actual AIAgent class and
module origin, check the 64 installed distribution versions (Hermes plus 63
dependencies), report module origins outside the verified runtime and exit.
No agent is constructed and no chat, model, skill, connector, memory-provider
attachment or authoritative business operation is invoked by the entry point.
There is no fake runtime, stub factory or patched governance candidate.

Imports themselves execute code: Hermes loads dotenv handling and discovers
tool modules; its discovery catches some optional-import exceptions and registers
cleanup handlers. Some initializers may attempt unsupported operations. Those
attempts remain subject to the existing token/network/process restrictions.
Successful AIAgent import does not establish optional-tool completeness, native
execution compatibility, constructor/shutdown readiness or governed operation.
All output-capture gaps, skipped optional modules and native timing remain limits.

## Package And Path Impact

The existing ProgramData/MayaProtectedPython-Startup1 location receives one new
attempt directory. Its read-only runtime contains the unchanged 806-file Python
payload, a product import check, the verified Hermes files under runtime/hermes,
dependencies under runtime/dependencies and a fixed distribution contract.
Hermes wheel data assets are mapped back to their pinned source-relative paths.
Dependency purelib/platlib data uses normal package locations; unused installer
scripts remain read-only payload data and are never invoked or placed on PATH.

The fresh state directory remains HERMES_HOME, USERPROFILE, LOCALAPPDATA and
TEMP/TMP, as in the existing launcher; the product additionally creates only
state/cache and state/logs. No operator home, .env or customer configuration is
copied. HERMES_DISABLE_LAZY_INSTALLS=1 is added to the child environment using
Hermes' supported opt-out. No machine environment setting changes.

Isolated Python uses explicit read-only Hermes/dependency paths. The pywin32
win32, win32/lib and Pythonwin import paths and pywin32_system32/win32 DLL paths
are explicitly scoped to that verified dependency directory. Arbitrary .pth
files are not executed. There is no editable install, online pip, user-site,
PYTHONPATH fallback, global Python installation or system DLL registration.

Every payload member retains a size and SHA256, safe relative path checks and
exact archive/index membership. The import profile permits 8,192 files and a
4-MiB index but preserves 32 MiB per file and 256 MiB expanded. Actual payload:
6,684 files, 143,209,647 expanded bytes and 952,392 index bytes.
All 63 downloaded wheels match published PyPI hashes/sizes, their internal
RECORD hashes/sizes and target Python/ABI/platform tags. Their complete base
dependency closure, including requested dependency extras, is checked without
importing them. Versions are frozen; no source/native build or installation.
All 821 nonmetadata Hermes source/data members match the existing pinned source
manifest. Seventy-six wheel license/notice files are retained separately, as
well as the original Python notices inside the runtime. These are provenance
checks, not a security audit or publisher signature claim.

## Unchanged Boundary And Lifecycle

Ordinary AppContainer, zero capabilities, reduced non-elevated same-user token,
one-process job, child-process policy, three inherited pipes and six scoped WFP
denies are unchanged. All transport remains denied, including localhost/model
services. No gateway exception, loopback exemption or extra resource grant.

There are no synthetic listeners, aliases, mapping or public-canary grants for
this import-only test. It does not need WFP event collection or change logging
settings. Existing elevated setup and independent child token checks remain.

The child has a 22-second cooperative import budget and the unchanged 30-second
host deadline. Profiling checks the cooperative budget on Python function calls;
it cannot interrupt every blocking native call. The host deadline remains the
outer stop boundary. Native import timing with this check is not yet measured.
Stdout retains the 4,096-byte cap and exact Python startup beacon. Imported text
output is bounded to 65,536 bytes and discarded rather than exposing raw logs;
the detailed report remains capped at 65,536 bytes. Native/direct-pipe output
can still invalidate the exact beacon and block acceptance.

After confirmed job stop, the host admits the bounded child report against the
immutable contract and retains it explicitly as untrusted evidence. Normal
grant/label/profile/filter cleanup uses the existing product path. Runtime files
and private reports remain. Larger extraction/hashing/ACL work is expected; no
automatic deadline increase, grant correction, retry or alternate launcher.
The journal-less recovery issue remains open; no forced-crash test is approved.

## Results

At most, a clean natural exit with exact beacons, matching class/origin/versions,
no outside-runtime module origin, bounded output and reported cleanup yields
import_completed_pending_independent_cleanup. Refusal, timeout, missing dependency,
wrong origin, native DLL failure, unreadable report or cleanup uncertainty blocks.
The result distinguishes Python entry from Hermes import and records the last
import stage, sanitized exception type and a bounded missing-module name where
available. It never exports an environment dump or raw exception message.

All production/containment/independent-cleanup qualification flags remain false.
Hermes construction, conversation, operational memory, all protected channels,
gateway authorization, models, connectors, Metabase, races and crash recovery
remain unqualified. Stop after the first result; do not rerun or change Windows
settings to obtain a pass. Separate manual cleanup review follows a native run.
